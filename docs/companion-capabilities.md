# Companion capability notes — research only

No companion is implemented, installed or enrolled in this PR. Android and Windows are proposed first; ChromeOS begins with browser coverage; iOS remains entitlement/privacy-gated. Inventory OS versions, account ownership, permissions and management before selecting a platform. Each future implementation needs a runnable capability spike and separate enrollment approval.

| Platform | Candidate capability | Limits and gate |
|---|---|---|
| Android | UsageStats app events/aggregates | Requires user-granted Usage Access settings; permission revocation and OS restrictions must show unavailable coverage. App usage is not URL history. [UsageStatsManager](https://developer.android.com/reference/android/app/usage/UsageStatsManager). |
| Windows | Foreground application plus idle/session intervals | Foreground window identifies an application/window, not browser navigation. Validate sleep, idle and multiple users. Website domains require a separately consented browser extension. [GetForegroundWindow](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getforegroundwindow). |
| ChromeOS | Active focused-tab domains through an extension | Browser-only coverage; Android/Linux/system apps need separate research. Managed school devices require school/organization administrator approval; do not assume force-install is available. [Tabs](https://developer.chrome.com/docs/extensions/reference/api/tabs), [distribution](https://developer.chrome.com/docs/extensions/how-to/distribute). |
| iOS/iPadOS | FamilyControls feasibility and on-device DeviceActivity reports | Distribution requires the Family Controls entitlement; report extensions have privacy/export restrictions. No promise of centralized detailed arbitrary app/site history. Entitlement approval and permitted export need evidence. [Entitlement](https://developer.apple.com/documentation/familycontrols/requesting-the-family-controls-entitlement), [report privacy](https://developer.apple.com/documentation/deviceactivity/deviceactivityreport). |

A proposed shared Chrome extension for Windows/ChromeOS could combine [window focus](https://developer.chrome.com/docs/extensions/reference/api/windows), [idle](https://developer.chrome.com/docs/extensions/reference/api/idle) and active-tab events for bounded domain intervals. Background tabs are not active use. Exclude paths/query strings by default; declare private-mode behavior and requested permissions. Android background delivery may be delayed; [periodic WorkManager](https://developer.android.com/reference/androidx/work/PeriodicWorkRequest) has a 15-minute minimum, unsuitable for precise real-time accounting.

Keep network requests, browser focus and application activity separate with provenance, coverage and freshness. Never sum overlapping devices/sources into screen time or treat DNS queries as proof of a visit. Enrollment/revocation, per-device credentials, signed updates, bounded buffering, consent, local retention and deletion require design before uploads. No keystrokes, screenshots, custom CA or decrypted URL collection is proposed. Router enforcement continues without companions; per-app restriction and outside-home controls are separate future capabilities.

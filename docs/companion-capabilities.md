# Companion capability notes — research only

No companion is implemented, installed or enrolled by this documentation. Android and Windows are proposed first; ChromeOS begins with browser coverage; iOS/iPadOS remains entitlement, privacy and region gated. Inventory OS versions, account ownership, permissions and management before selecting a platform. Each future implementation needs a runnable capability spike and separate installation/enrollment approval. Platform observations below were checked against official documentation on 2026-10-12; device behavior and control effectiveness remain unverified.

| Platform | Observation candidate | Coverage and feasibility limits |
|---|---|---|
| Android | `UsageStatsManager.queryEvents(begin, end)` app events | This method requires `PACKAGE_USAGE_STATS` access granted through Settings; requirements differ across usage methods. Events persist only a few days, and Android R onward returns null when `UserManager.isUserUnlocked()` is false, such as before credential unlock after reboot. Reconstruct intervals with explicit gaps and unavailable coverage after revocation. App activity is not website history. [UsageStatsManager](https://developer.android.com/reference/android/app/usage/UsageStatsManager). |
| Windows | Foreground application plus idle/session intervals | [GetForegroundWindow](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getforegroundwindow) can return null. [GetLastInputInfo](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getlastinputinfo) covers the calling session, not all users; its tick value is not strictly increasing. Sampling misses transitions. Validate idle, lock, sleep and multiple users; resolve app identity without collecting window titles. Domains require a separately consented browser extension. |
| ChromeOS | Active-tab domains in focused Chrome windows | URL access needs `tabs` or matching host permission; `activeTab` is temporary after user invocation. Browser coverage excludes Android/Linux/system apps. Managed school devices require school/organization administrator approval; do not assume force-install is available. [Tabs](https://developer.chrome.com/docs/extensions/reference/api/tabs), [distribution](https://developer.chrome.com/docs/extensions/how-to/distribute). |
| iOS/iPadOS | Authorized FamilyControls and on-device DeviceActivity reports | Child authorization requires guardian consent through Family Sharing. Distribution requires [Family Controls entitlement approval](https://developer.apple.com/documentation/familycontrols/requesting-the-family-controls-entitlement). Ordinary [DeviceActivityReport](https://developer.apple.com/documentation/deviceactivity/deviceactivityreport) extensions are sandboxed against networking and moving report data outside their address space. This route does not establish centralized detailed app/site history. [FamilyControls](https://developer.apple.com/documentation/familycontrols). |

Apple's distinct [FamilyActivityData](https://developer.apple.com/documentation/familycontrols/familyactivitydata) route exposes raw bundle identifiers/domains with [`approvedWithDataAccess`](https://developer.apple.com/documentation/familycontrols/authorizationstatus/approvedwithdataaccess) and the Family Controls App and Website Usage entitlement. Production eligibility requires both an EU device location and an EU Apple Account. Development testing outside the EU does not establish production eligibility. Exact SDK minimums and entitlement availability need confirmation before a spike; ordinary report restrictions must not be generalized into a claim that all Apple usage-data export is impossible.

A proposed shared Chrome extension for Windows/ChromeOS could combine [window focus](https://developer.chrome.com/docs/extensions/reference/api/windows), [idle](https://developer.chrome.com/docs/extensions/reference/api/idle) and active-tab events for bounded domain intervals. Background tabs are not active use; an active tab in an unfocused window is not focused use. Declare private-mode behavior and requested permissions. Android background delivery may be delayed; [periodic WorkManager](https://developer.android.com/reference/androidx/work/PeriodicWorkRequest) has a 15-minute minimum, unsuitable for precise real-time accounting.

Observation, control and tamper resistance need separate evidence. Usage APIs and foreground sampling do not prove blocking. Supported app/browser controls, outside-home enforcement, permission removal, extension shutdown and user termination require distinct spikes. Router enforcement continues without companions; none of these proposed observations adds policy authority or establishes resistance to tampering.

The common protocol is planned, not implemented. Parent-owned enrollment would assign an opaque companion device ID independently of changing MAC addresses. Client telemetry remains self-reported: device assertions cannot establish a trusted MAC binding. Any relationship to network inventory needs independent parent-confirmed evidence. A separately reviewed telemetry contract must preserve existing parent/admin policy boundaries.

Per-device credentials should permit only bounded telemetry uploads, never pause, resume, assignment or policy changes. Design rotation, reinstall, reassignment and revocation before collection. A versioned envelope should carry source/coverage, OS/app version, permission/consent state, applicable region eligibility, event interval, receipt time, sequence and enrollment epoch. Bound batch size and offline queue age/quantity; validate schemas, reject replay, deduplicate retransmissions and declare loss or clock discontinuities. Revocation must invalidate credentials and stop uploads. Signed updates and credential storage need review.

Keep network bytes, DNS, browser focus and application intervals separate with provenance, uncertainty, coverage and freshness. DNS queries do not prove visits; foreground apps do not prove engagement. Never blindly sum overlapping devices/sources into screen time. Default to app identifiers and domains without paths/query strings, window titles, adult-profile collection, keystrokes or screenshots. No custom CA or decrypted URL collection is proposed. Define local/server retention, deletion, shared-profile exclusions and parent-visible consent/revocation status before uploads. Independent review and fictional failure fixtures should precede separately approved device checks.

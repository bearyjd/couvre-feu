# Router admission facts

Audit baseline: branch `feat/vendor-admission-usr-share`, commit `088b9e0`. This is an exhaustive inventory of the reachable install-validation/admission assumptions reviewed here, not a hardware admission or permission to contact a router. No router, SSH host, init service, firewall backend, installer or uninstaller was invoked to prepare it. File:line anchors refer to that commit; later source changes require a new review.

The table targets an explicitly selected `gl-xe3000-4.8.3-os-trust-v1` production install/uninstall unless a row states 011-only, optional or another branch. Strict rejects vendor write exceptions and does not execute vendor attestation. OS-trust does not execute the 011 population census. A static row is a necessary point-in-time witness, never a successful transaction verdict. All runtime rows remain UNOBSERVABLE by this collector. The expected first known metadata refusal is `/usr/share` mode 0775: the service-source gate accepts only 0755 there, despite other named vendor ancestry exceptions.

Stable machine IDs use `path:/absolute/path:field`, `runtime:name`, `tool:name:present`, `system:name` and `probe:format`. JSON arrays enumerate accepted capture values; numeric min/max objects constrain decimal sizes; metadata predicates require owner 0:0 and 3–4 octal digits with mask 07022 clear, apart from listed exact modes. JSON `{"observable":false,"reason":"..."}` always produces UNOBSERVABLE rather than PASS. Optional-path metadata/size is skipped only when the same capture proves that permitted path missing. An omitted required fact, unreadable input, unsupported tool or unknown dynamic prerequisite must remain missing/UNOBSERVABLE. A successful static comparison cannot become an overall admission pass. Never treat a partial fixture as completed admission. Parent canonicalization and type are separate checks: a real final component can still have linked ancestry.

Captures may disclose numeric metadata and fixed-path digests, never account bodies, group membership, MACs, policies, raw mountinfo, configuration, transaction tokens or process credential dumps. A read-only capture does not authorize changes or live acceptance. The companion probe/checker describe their own usage; each exact router invocation, including reads, still requires separate user approval under AGENTS.md.

Read-only field legend: `type` uses symlink-first `test -L`, then `test -d`, `test -f`, and existence tests without following an ordinary input link. `metadata` uses numeric `stat -c %u:%g:%a`; `size` uses `stat -c %s`; `links` uses `stat -c %h`. `canonical` compares literal ancestry with `CDPATH= cd` and `pwd -P` in a subshell; for a directory it also checks that directory itself. `sha256` hashes only an admitted fixed regular file and returns lowercase digest, with a collector size cap; no file body is printed. `link` uses `readlink` only on the three documented literal-link exceptions, and emits OTHER for any unexpected target. Every observation is sanitized and bound to its ID, and unsupported/read failures emit UNOBSERVABLE. Tool presence uses fixed-PATH `command -v`; it does not execute those dependencies. Refer to the probe implementation for its own supported capture grammar and numeric-output validation.

# Enforcement contract — router core v2

This describes the current router implementation, not completed packet acceptance. The original [PRP-001](prp/PRP-001-enforcement-core.md) is preserved; its corrected implementation choices are explicit below. The local fake-router service and PWA are specified separately in [PRP-003](prp/PRP-003-policy-service.md) and [PRP-002](prp/PRP-002-parent-pwa.md). [Acceptance gates](acceptance-001.md) govern target runtime, packet behavior and separately approved live actions.

## Commands and confirmation

`cfctl status --json`, `pause <person> [--until <epoch>]`, `resume <person>`, `sync` (JSON stdin), `expire`, and `apply-fw` implement control/reconstruction. `check` is a read-only dependency/parser probe. `remove-fw` is internal recovery and unavailable through `cfctl-ssh`; the wrapper accepts only its explicit control grammar without shell evaluation. Status can exit zero with uncertainty; mutations fail nonzero on failed application. Require JSON `ok`, matching revisions, no drift/errors and sufficient observed evidence, not merely an exit code.

Status fields:

| Field | Meaning |
|---|---|
| `ok` | Current observation agrees with accepted policy and runtime confirmation |
| `desiredRevision`, `confirmedRevision` | Durable desired revision and runtime-confirmed revision; confirmation can be null |
| `desiredPauses`, `effectivePauses` | Stored pause records versus unexpired manual pauses (a pause stays effective while an allowance overrides it) |
| `desiredAllowances`, `effectiveAllowances` | Stored allowance records versus honored allowances, with `until` and `remaining` seconds from the router expiry epoch |
| `observed.kids`, `observed.paused` | Actual MAC set observations |
| `drift`, `errors` | Mismatch, interrupted application, busy transaction or other uncertainty |
| `capabilities.ipv6`, `.conntrack`, `.nativeKernelConfirmed` | Backend observations; no guarantee of end-to-end packet acceptance |
| `capabilities.addressCoverageComplete` | Whether required active pause/schedule address coverage is established; gaps return `incomplete_address_coverage` |
| `capabilities.routerCompatibilityVerified` | Explicitly false until separately established compatibility; the current implementation does not assert it |

A successful dependency probe or native-rule witness cannot establish the five-second cutoff, adult DNS safety, acceleration coverage or firmware durability.

## Desired JSON

Required top-level fields are `version:1`, integer `revision`, `people`, `pauses`, `schedules`; optional `allowances` is an array; optional `doh` requires both address arrays when present. Unknown/duplicate keys, invalid values and conflicting/shared MAC assignment are rejected. The [README](../README.md) provides a fictional example.

| Entity | Fields and bounds |
|---|---|
| People | `id`, `macs`; up to 64 people, 32 MACs/person, 256 MACs total |
| IDs | Lowercase ASCII letter first, then lowercase letters/digits/underscore; at most 32 characters |
| MACs | Canonical lowercase colon-separated nonzero unicast addresses, unique across all people; empty person device list permitted |
| Pauses | `person`, `until`; one per defined person, at most 64; 0 indefinite, otherwise absolute epoch |
| Allowances | `person`, `until`; one per defined person, at most 64; `until` is a positive absolute epoch (1–2147483647). A newly staged allowance that has not expired must end at most 14400 s after router time |
| Schedules | `person`, `id`, `weekdays`, `start`, `stop`; defined person, unique person/schedule ID, at most 256 input schedules |
| Weekdays / clocks | Unique nonempty subset of Mon–Sun; `HH:MM` in 00:00–23:59; equal start/stop rejected |
| Expanded windows | At most 256 total per-device native windows after cross-midnight expansion; input count alone is insufficient |
| DoH | `ipv4`, `ipv6`; at most 256 unique addresses each; IPv6 addresses canonicalized for duplicate detection |
| Integers | Canonical nonnegative integer syntax, at most 2147483647 for revision/epoch |

The shipped strict POSIX awk parser accepts a bounded ASCII subset: strings/keys must contain no escapes, Unicode or control characters. Input is limited to 65536 bytes, depth 12, 8192 nodes and 128 characters/string. Sync stages and validates stdin before acquiring the mutation lock, using a ten-second read deadline (`timeout 10 dd ...`). A callable `/usr/bin/timeout` or `/bin/timeout` is a new required dependency; its availability and behavior on the actual router were not established by the spike. The explicit fixture hook `CF_TEST_TIMEOUT="busybox timeout"` exercises genuine BusyBox timeout when available; production uses only the trusted fixed paths. Host/CI timeout behavior cannot establish target compatibility. This deliberately excludes valid general-purpose JSON encodings; future clients must emit this subset, not assume arbitrary JSON serialization is compatible. Actual target ash/awk runtime remains a gate.

Changed policy needs a newer revision; identical normalized same-revision sync is idempotent, and conflicting/stale revisions fail. Pause/resume advance the revision. Resume removes only manual pause; an active schedule still blocks. The router-local allowance below is the only temporary unblocking mechanism.

## Allowances

`"allowances":[{"person":"<id>","until":<epoch>}]` is optional. Without it, the state, JSON and digests are byte-identical to earlier releases.

- **Semantics.** The allowance is honored while router expiry time is before `until`. During that time the person's pauses (indefinite or timed) and schedules are taken out of the ungated enforcement view: the paused set, the ungated `cf2_*` schedule rules and the native `cf_sched_*` sections. They are not removed from policy.
- **Kernel-side expiry.** The person's block rules are not dropped while the allowance is active. The owned early hook installs them gated by a second `-m time --datestart <until as UTC YYYY-MM-DDThh:mm:ss>` match (xt_time defaults to UTC, so the rule has no `--utc`/`--kerneltz` flag):
  - per-MAC outbound and per-address inbound REJECTs for any pause still in force at `until`;
  - each schedule window, keeping its existing `--weekdays/--timestart/--timestop --kerneltz` match.

  At `until` the kernel blocks again even if cron, the service or the shell clock has failed. The early hook sits before established acceptance, so established flows are rejected too; only offloaded flows wait for cron eviction. `cfctl expire` then rebuilds the ordinary ungated form, so a missed cron is harmless.
- **Native sections.** Native fw3 `cf_sched_*` sections cannot carry a datestart in the generated UCI, so they stay dropped during an allowance. The early gated mirror enforces from `until`, and `expire` restores the sections. The same `xt_time` module already serves schedules (spike 001 recorded `xt_time` loaded on iptables 1.8.7 legacy / Linux 5.4). `--datestart` itself has not been exercised on the live router and remains a live gate, as does the `--kerneltz` behavior. The person stays in `cf_kids`, so DNS redirection, the DoT/DoQ/DoH blocks and the LAN DNS input exception still apply exactly as for any unblocked child.
- **Expiry.** Expiry works like timed-pause expiry. The minute cron `cfctl expire` sees the changed effective digest and reconstructs through the same transition path, without the service, within normal cron tolerance (about one minute). Expired allowance records are retained, like expired pauses. Expiry therefore never changes revision or policy digest, CAS bases stay valid, and an identical same-revision replay is idempotent and cannot resurrect the allowance. The highwater expiry epoch prevents a backward clock jump from re-honoring an expired allowance.
- **Admission.** Admission uses the json.awk static bounds (unique known person, `until` ≥ 1) and, for local `sync` and `rpc-sync`, the router-time horizon: an unexpired allowance more than 14400 s ahead fails with `allowance_beyond_horizon`. Already-expired allowances are accepted and stay inert.
- **Fail-safe.** An allowance is honored only when the epoch is a valid post-2020 clock and `now < until <= now + 14400`. Otherwise it is ignored and the person is blocked. With an invalid clock, mutating commands refuse and status reports `effectiveAllowances: []` with `ok:false`.
- **Precedence.** At the router, an active allowance wins over pauses and schedules, including a later `cfctl pause`. The service decides precedence: for example, a new parent pause should clear the allowance in the same policy revision.
- **Residual gaps.** The gate follows the kernel's real-time clock: if the clock is set backwards across `until`, the gate deactivates until the clock passes `until` again. Accelerated (offloaded) flows are evicted only by the next cron run. A full firewall restart without the include drops all owned rules, as before.

## Durable state and safety

One atomically replaced normalized TSV file, `/etc/couvrefeu/state`, stores version/revision, person-to-MAC ownership, manual pause metadata, schedules and DoH addresses. This replaces the PRP's raw MAC/expiry format. Record kinds are `V`, `R`, `P`, `A`, `U` (allowance), `S`, `D4`, `D6`; clients use JSON rather than editing TSV. Expired pause metadata can remain for replay equality, while effective membership excludes it.

Persisted protection, serialized mutation locks, confirmation/error records, firewall snapshots/intents and expiry high-water are auxiliary runtime/recovery data. Clock values before 2020 are rejected; expiry uses the greater of current clock and persisted high-water to resist resurrection after backward jumps. Minute cron re-evaluates policy without a service; clock/cron health and target boundary latency remain acceptance conditions. BusyBox crond (1.33) rescans `/etc/crontabs` only when the directory's whole-second mtime changes, on `cron.update`, or hourly, so a temporary crontab and its rename in one second can stay unseen for up to an hour. After every crontab change install and uninstall therefore run `/etc/init.d/cron reload`. Under the OpenWrt 21.02 procd script this registers each crontab's md5: it restarts crond only when a crontab changed, starts a crond that is not running (the script never starts crond while `/etc/crontabs` is empty), and stops crond when `/etc/crontabs` is empty again. Its exit status is not evidence, and a non-procd script answers unknown actions with `help` (exit 0), so install proves the instance through procd itself (`ubus call service list '{"name":"cron"}'` with `jsonfilter -e '@.cron.instances[*].running'` reporting `true`) and otherwise fails without reporting success. Before the first protected write, install refuses with `no installation made` unless `/etc/init.d/cron` is an executable procd script (`USE_PROCD=1`) and `/etc/init.d/cron enabled` succeeds: a crond that does not start at boot would stop minute expiry after a reboot. The init script, `ubus` and `jsonfilter` run under `env -i PATH=/usr/sbin:/usr/bin:/sbin:/bin LC_ALL=C`. Uninstall signals after verified exact restoration and only warns on failure. Uninstall's reload compares the restored crontabs against the md5 procd recorded at its last reload, not against the table crond actually loaded. If they diverge (for example, an install whose reload failed after crond's own mtime rescan had already loaded the installed table), restoring bytes that match procd's record leaves crond running with the stale `cfctl expire` entry until its next rescan, at most an hour. The impact is low: uninstall has already removed `/usr/sbin/cfctl`, so that entry fails to execute and changes nothing. `cron.update` is not used: it is consumed only by a running crond, and a left-over file would be an unjournaled entry in a managed directory.

Protected MAC overlap is refused. Current SSH-client identity must resolve uniquely from validated LAN observations for controlling operations; absence of SSH context does not erase persisted protection for cron/include. Address/lease data are treated as data, never executed. Unknown devices are not quarantined and rotating identities remain a coverage limit.

## Firewall behavior and deviations

Both families use an unconditional early jump to `cf_fwd` before established acceptance; rules inside it remain LAN/interface scoped. Manual pause and schedule mirrors cover outbound source MACs and inbound destinations on `-o br-lan`, using verified current child IP mappings. This closes the inbound established UDP path across a schedule boundary; real packet proof remains pending. Protected destination mappings return without child enforcement. Child IP rules/conntrack eviction require unique fresh attribution through a current DHCP lease (expiry 0 or in the future) or REACHABLE/PERMANENT neighbor observation. Uncertain child addresses are omitted; plausible protected bindings retain destination exclusions even when stale. Strict sync/pause reject missing coverage when an active pause/schedule needs it. Expire/resume/apply-fw can still reconstruct safe rules and clear obsolete MAC/IP enforcement during coverage gaps, but must not report healthy active coverage: `addressCoverageComplete=false` and `incomplete_address_coverage` remain explicit. With no active pause/schedule, stale/offline children need no address proof for confirmation. Omitted neighbor `dev` is accepted only from the fixed `br-lan` collector; IPv6 destination host forms permit only /128, not broader prefixes. DNS-port and DoH destination rejects remain kids-source scoped. Native schedule rules also persist as owned fw3 sections. Cross-midnight windows split at midnight and rotate the second half's weekdays; exclusive stop boundaries become inclusive kernel stops one second earlier. Native `utc_time=0` and early `--kerneltz` use router local-time semantics, subject to timezone/DST acceptance.

Native rules explicitly set `proto=all`: fw3's omitted-protocol default would cover TCP/UDP only. `dest=wan,target=REJECT` may compile through `zone_wan_dest_REJECT` to `reject`, rather than a direct REJECT. Verification requires the complete supported named MAC/time rule in both families, with no extra selectors, and checks earlier rule/chain reachability so a preceding ACCEPT/RETURN cannot silently shadow it. Earlier called chains must have supported non-ACCEPT behavior; unknown nested paths remain pending. The read-only existing `fw3 -q zone wan` command resolves a bounded validated list of concrete WAN devices; the reject path must match exact members and cover all listed devices. Empty, wildcard, partial or unknown mappings keep confirmation pending. This performs no WAN configuration write. Native edits use a private UCI configuration directory (`-c`) and private delta directory (`-t`), then validated journaled replacement/reload; they must not commit unrelated saved deltas.

These choices were checked against official [fw3 rules.c](https://github.com/openwrt/firewall3/blob/master/rules.c), [fw3 main.c](https://github.com/openwrt/firewall3/blob/master/main.c) and [UCI cli.c](https://github.com/openwrt/uci/blob/master/cli.c). No upstream source was copied. Native zone rules alone cannot stop established traffic; broken-helper fallback does not promise stream cutoff.

IPv4 kids TCP/UDP external DNS is DNATed to the validated LAN router address; a narrow kids-only UDP INPUT allowance precedes GL leak protection. IPv6 forwarded TCP/UDP port 53 is rejected rather than NAT6 redirected; local kids UDP DNS allowance uses validated observed router IPv6 addresses. This is a PRP deviation, not a claim that local IPv6 DNS or GL integration is verified. No dnsmasq/WAN configuration change is included. Existing GL controls and protected adults must remain unaffected.

## Unchanged reconciliation and reconstruction risk

Healthy unchanged expire/apply-fw and identical same-policy/same-revision sync can avoid reconstruction only after validating private ownership/confirmation metadata and digests, exact snapshot, actual sets/rules/hooks, persistent native section types/selectors and kernel witnesses, and fresh address/protection evidence under the lock. The shortcut preserves kernel objects. Every minute reconciliation still drains fresh uniquely attributed clients with an effective manual pause or active schedule, in both address families and directions. The private schedule clock record stores the evaluated minute, local clock and UTC offset; it is evidence of evaluation, not proof of kernel timezone or acceleration behavior. Checked raw-chain command failures are handled before normalization pipelines, so a failed read cannot become a healthy empty observation.

Address/protection/effective-membership/configuration changes, drift and missing objects invalidate the shortcut and require actual repair. A higher revision with identical verified kernel behavior can update its confirmation without rebuilding. Manual pause and changed enforcement retain scoped connection eviction. Persistent native section/type/full-selector validation also runs in status, preventing stale private metadata from masking persistent configuration drift.

Normal online policy changes stage an immutable complete inactive generation before durable policy/receipt acceptance. Stable `cf_fwd`, `cf_input` and IPv4 `cf_dns` dispatchers keep their exact early parent hooks. Two bounded slots, `a` and `b`, contain filter chains `cf2_<slot>_f`, `cf2_<slot>_i`, temporary guard `cf2_<slot>_g`, IPv4 NAT chain `cf2_<slot>_d`, and sets `cf2_<slot>_k`/`p` (MACs), `d4`/`d6` (DoH addresses) and temporary `u` (old/new child union). These set names deliberately replace PRP-001's `cf_kids`/`cf_paused`/`cf_doh`: immutable referenced sets prevent an online set flush from opening enforcement. V1 installations require exact uninstall/reinstall; automatic migration is refused.

The transition descriptor is a root-owned private, versioned, bounded exact inventory, written using sync–rename–sync before effects. It binds the installation generation, old/new accepted digests, receipt identity, boot ID, prepared expiry, address/protection witnesses, ordered plans and recovery phase. Ordered prefixes are recognized only during unreachable staging; complete prepared objects, exact pending stale-selector removal, complete old/new dispatcher targets and guarded mixed-family states are recognized during exposure. Foreign additions/references refuse cleanup; an object prefix never authorizes deletion. A staged proposal whose digest was not atomically accepted is abandoned without exposing it. New transactions stop until prior recovery is resolved.

Before any of the five single-rule dispatcher replacements, both forwarding families carry a prepared guard for the union of old/new child identities. Protected source MACs and protected destinations return before child drops; fresh unique child reverse addresses are guarded separately. Scoped conntrack deletion runs before switching and again before removing guards. Complete family, native, DNS, set, hook and fresh identity witnesses are required before exposing the accepted generation. A failure can leave the old generation, complete accepted generation or a conservative guard in different families, with explicit uncertainty. Cleanup never flushes a reachable active generation. This is a guarded sequence, not one globally atomic transaction.

Fail-closed staging: changed policy, drift repair and selective-reload repair all use this path; there is no v1-style live set flush, chain flush or parent-hook delete/insert. Until the first dispatcher replacement, the only effects are creation/population of the inactive slot, the guard insertion at `cf_fwd` position one, scoped conntrack deletion, the journaled native update and one exception in the active slot: `cf_stale_repair` may first delete exact, journaled inbound reverse-destination selectors whose address is no longer uniquely attributed to a child (for example, now held by a protected adult). Source-MAC blocking is unaffected by that removal. Any failure exits nonzero with the old generation still dispatched and otherwise unchanged; the previous confirmation remains historical. An interrupted or failed staging whose digest was not accepted is abandoned by the next ordinary run (`cf_slot_delete` of the unexposed slot); uninstall inventories and removes either slot, guards and union sets. After a killed process the installer still refuses while its stale runtime lock remains; one ordinary run first recovers the lock and abandons the unexposed slot. The switch primitive is a fixed-position `-R`: legacy iptables reads the whole table, edits it in userspace and commits it with one `IPT_SO_SET_REPLACE`/`IP6T_SO_SET_REPLACE`, so each table/family atomically sees the old or new jump. This assumes the legacy xtables backend; an `iptables-nft` compatibility backend commits through nftables transactions instead, and the GL firmware's backend is unverified. `iptables-restore --noflush` would give the same per-table commit but no cross-family or filter/nat atomicity, and `ipset swap` would mutate referenced live sets; neither is used. `-w 5` serializes against other xtables-lock users only; a writer that ignores the lock can still race the read-modify-write. Native fw3 sections are a separate persistence layer committed before the switches: an intermediate failure can leave native REJECT rules for the new policy beside the old early generation, which only adds blocking until retry. Fixtures assert ordering against modeled rulesets captured after every mutating command; they do not measure kernel commit behavior, fw3 custom-chain preservation on the GL firmware or offload.

Expiry/resume may remove exactly inventoried obsolete reverse selectors when a child is offline or an address belongs to a protected adult; they never guess a replacement binding. An effective blocked child still needs fresh coverage for confirmation. An accepted transition interrupted across expiry can finish a verified complete conservative generation without publishing health, then stage the current effective policy under a new guard. Recovery is bounded to two transitions per invocation; a further clock/evidence change stays unconfirmed for the next reconciliation. No unsafe stale reverse selector is restored during that recovery.

Selective native reload must preserve dispatchers, immutable generations, staged objects and guards; reinspection requires both complete guard bodies and the exact typed union set before any dispatcher replacement. Missing, truncated or emptied guards stop switching and remain unconfirmed. The exact installed vendor reload path remains a live activation gate. A full restart/reboot or externally absent firewall has a separate degraded reconstruction contract: accepted policy is reconstructed and freshly verified, with no packet-continuity claim while hooks/tables are absent. Boot ID changes invalidate prior runtime confirmation. PRP-001's failed-helper pause fail-open limit remains in force; native fallback alone cannot establish established/reverse/offloaded stream cutoff.

Kernel schedule matches enforce their boundaries for traffic reaching netfilter. Minute cron provides supplementary scoped eviction for active schedules even when policy is unchanged. It does not promise a five-second scheduled cutoff through enabled acceleration; real offload draining, cron timing and router/kernel timezone/DST behavior remain mandatory live gates. No global acceleration setting, WAN zone or dnsmasq configuration is changed. Manual pause retains its separately measured five-second acceptance requirement.
Kernel cleanup first writes an atomic private `runtime/firewall.cleanup` inventory through a `.cleanup.<pid>` temporary file. Retry verification permits recorded exact remaining objects, already-flushed empty owned chains, or absent objects; remaining sets must be unchanged or absent. Foreign references, additions or modified remaining objects are refused. The intent prevents ordinary mutation until internal recovery resumes. Durable uninstall markers and `/etc/.couvrefeu-recovery`/`.done` also block sync, pause, resume, expire and apply-fw before and after locking, even between transient installer locks; only the authenticated installer remove-fw handoff may bypass the filesystem recovery barrier. Status/check remain read-only. Pending `.next` phase markers also gate ordinary mutations. A validated explicit zero-owned-kernel-mutation cleanup proof persists the `no-kernel-mutations` phase; uninstall alone may then skip original-firewall reload to preserve foreign objects. Partial owned mutation still requires cleanup and reload. Activation failure alone never authorizes skipping reload.

Installation defaults to staging and requires explicit activation. Exact-original recovery, drift refusal and resumable uninstall phases are described in the [runbook](acceptance-001.md). Exact-original identity is content and metadata (sha256, size, mode, owner, nanosecond mtime), never dev:ino. On the GL-XE3000 (OpenWrt 21.02) root overlay without `index`/`xino`, a file copied up with an origin reports the overlay dev with the lower inode while a new hard link to it reports another dev:ino, and hard-linking a lower-only file copies it up; see the [runbook](runbooks/live-first-rehearsal.md#measured-overlayfs-identity-gl-xe3000-openwrt-2102-2026-10-14). Originals therefore move into the journal and back by same-filesystem rename (proved before any change), which keeps their metadata without `touch`, and are proved after each rename. Neither file preservation nor local fixtures establish live compatibility. Known DoH lists are limited and have no implemented service refresh owner; cellular/VPN/unknown identities remain outside the claimed coverage.

An existing malformed or symlink ownership marker refuses removal. With no marker, cleanup enumerates actual private runtime entries and inspects both families, all inspected tables, sets and native schedule configuration before claiming zero kernel mutations. A valid initial staging descriptor written before the first ownership marker can be removed, together with exact validated journal temporaries, only after that zero-effect proof. Unknown runtime entries and unowned kernel effects preserve journals and prevent uninstall from suppressing its restoration reload.

Authenticated installer activation records a private, durable `firewall.preflight` baseline before initial enforcement preflight, binding the current state/generation and the complete inspected rule, set and UCI inventories. A preflight refusal may therefore preserve a foreign object with a colliding name. File restoration can skip kernel cleanup/reload only when ownership/transition/confirmation records are absent and fresh inventories exactly match that recorded baseline. The validated baseline remains through `remove-fw` and failed handoffs; installer runtime cleanup removes it after recording `kernel-cleaned`. Baseline drift refuses restoration and preserves helpers and journals. Successful preflight removes and syncs the baseline before transition preparation or enforcement effects; ordinary mutations cannot bypass a retained installer baseline. Absence of an ownership marker alone supplies no such evidence.
